## 1. 项目概述与愿景

### 1.1 项目背景

中国高血压患者超 2.45 亿，其中老年群体占比超过 60%。当前慢病管理面临三大核心痛点：

- **认知障碍**：老年人对疾病认知不足，用药依从性差
- **情感缺失**：空巢老人缺乏情感支持，焦虑抑郁影响康复
- **数据断层**：健康数据分散，无法形成有效的个性化干预闭环

### 1.2 产品定位

**一句话定位**：基于斯坦福大学慢性病自我管理项目（CDSMP）理论框架，以适老化智能终端为载体，融合多Agent协作、动态时序知识图谱与大语言模型技术，为高血压老年人提供"有温度、有记忆、能成长"的全天候自我管理智能伙伴。

### 1.3 核心创新点

| 维度 | 创新内容 |
|------|----------|
| **理论驱动** | 首次将斯坦福CDSMP框架系统性地映射为多智能体行为模型 |
| **记忆架构** | 放弃传统RAG，采用动态时序知识图谱，让AI真正"认识"每位老人 |
| **安全范式** | Agent C 医疗监察机制 + Human-in-the-Loop 双重保障 |
| **交互范式** | 适老化多模态交互，支持方言识别、情感语音合成、大字体UI |

## 2. 理论内核：斯坦福CDSMP框架

### 2.1 框架简介

斯坦福大学患者教育研究中心（Stanford Patient Education Research Center）开发的慢性病自我管理项目（Chronic Disease Self-Management Program, CDSMP），是全球循证医学领域最成功的慢病管理干预模型之一，已被全球 30+ 个国家引进并验证有效。

### 2.2 CDSMP 六大核心能力

```
┌─────────────────────────────────────────────────┐
│            CDSMP 六大核心能力模型                  │
├─────────────────────────────────────────────────┤
│  1. 行动计划制定 (Action Planning)               │
│     → SMART 目标分解，每周小步前进                  │
│  2. 决策制定 (Decision Making)                    │
│     → 面对健康变化时的分析-决策-行动能力              │
│  3. 资源利用 (Resource Utilization)               │
│     → 识别并使用社区、家庭、医疗资源                 │
│  4. 患者-医疗提供者伙伴关系 (Patient-Provider       │
│     Partnership)                                 │
│     → 有效沟通、主动提问、共享决策                   │
│  5. 情绪管理 (Emotion Management)                 │
│     → 应对恐惧、焦虑、抑郁、挫败感                   │
│  6. 自我效能 (Self-Efficacy)                      │
│     → "我能行"的信念，核心驱动力                    │
└─────────────────────────────────────────────────┘
```

### 2.3 CDSMP 三大干预策略

| 策略 | 描述 | 在本系统中的实现 |
|------|------|------------------|
| **掌握经验 (Mastery Experience)** | 通过小目标的达成积累成功经验 | Agent A 引导制定微小行动计划，完成后给予真诚肯定 |
| **替代经验 (Vicarious Experience)** | 通过榜样学习增强信心 | Agent A 分享相似背景病友的成功案例（脱敏处理后） |
| **社会说服 (Social Persuasion)** | 来自他人的鼓励和支持 | Agent A 的共情对话、家人的鼓励语音、社区医生认可 |

### 2.4 框架与Agent A的映射关系

```
Agent A（健康教练）能力树

│   └── 紧急情况判断
├── 资源导航员
│   ├── 社区服务推荐
│   ├── 就医时机建议
│   └── 家庭支持动员
├── 沟通赋能师
│   ├── 就诊问题清单生成
│   ├── 医疗术语翻译
│   └── 复诊提醒与准备
├── 情绪守护者
│   ├── 负面情绪识别
│   ├── 认知重构引导
│   └── 放松训练指导
```

## 3. 硬件终端形态设计

### 3.1 形态一："健康守护相框"（主推形态）

**设计理念**：将智能终端伪装成家庭中已有的、无侵入感的物品——电子相框。降低老年人对"医疗设备"的抗拒心理。

```
│  │                          │    │

│  │                          │    │
│  └──────────────────────────┘    │
│                                  │
│  [🔊 远场麦克风阵列]  [📷 摄像头]  │
│  [🔈 大音量扬声器]    [🔴 SOS键]  │
│                                  │
│  底座内置：                       │
│  - 智能药盒（7格/周，声光提醒）    │
│  - 无线充电板（为血压计充电）      │
│  - 蓝牙网关（连接血压计等设备）    │
```

**核心优势**：
- 日常状态显示家人照片，消除"被监护感"
- 主动语音唤醒，不需要老人操作屏幕
- 药盒与相框一体化，解决"忘吃药"核心痛点

### 3.2 形态二："智能药盒基站"（轻量替代形态）

**设计理念**：以智能药盒为核心，搭配手机APP使用，适合有一定智能手机使用能力的老年人。

**核心功能**：
- 7格智能药盒，带独立LED灯和蜂鸣提醒
- 内置 4G 模块，可独立联网（不依赖WiFi）
- 一键呼叫AI健康教练（语音通话模式）
- 低功耗设计，充电一次使用两周

### 4.2 Agent A：健康教练（前台交互层）

**角色定义**：直接面对老年用户的对话智能体，是系统的"脸面"和"嘴巴"。

**核心职责**：
- 以适老化的语气和节奏与老人进行语音对话
- 所有回复必须遵循斯坦福 CDSMP 框架的干预策略
- 引导老人制定行动计划、管理情绪、提升自我效能

**Prompt 模板示例**：
```markdown
# 角色：你是一位经验丰富、温暖亲切的社区健康教练。

## 核心原则
1. 永远不要使用恐吓性语言（如"不吃药会中风"）
2. 使用"我们"而非"你应该"
3. 每次对话结束时，引导老人完成一个微小行动

## CDSMP 策略应用
- 当老人表达困难时 → 运用"掌握经验"策略，回顾过去的成功
- 当老人感到焦虑时 → 运用"情绪管理"策略，引导深呼吸放松
- 当老人取得进步时 → 运用"自我效能"策略，真诚肯定

## 对话示例
用户："我不想吃药了，每天都吃，烦死了"
错误回复："停药可能导致血压升高，引发中风等严重后果"
正确回复："王大爷，这药确实天天吃挺烦的。您能坚持这么久，
         真的很了不起！咱们想想，上次您血压控制好的时候，
         是不是还带着小孙子去公园了？咱们再坚持一周，
         周末让女儿带您去吃那家您最爱的无糖糕点，好不好？"
```

### 4.3 Agent B：记忆局长（数据中枢层）

**角色定义**：负责维护和管理用户的动态时序知识图谱，是系统的"大脑"和"记忆"。

**核心职责**：
- 实时从对话中抽取医疗实体（血压值、症状、用药、情绪、生活事件）
- 将实体以带时间戳的节点和边写入 Neo4j 图谱
- 根据当前对话上下文，检索相关历史记忆供其他 Agent 使用

**实体抽取示例**：
```
用户输入："今天早上量血压155/95，有点头晕，昨晚没睡好"

Agent B 抽取结果：
{
  "timestamp": "2026-07-29T07:30:00+08:00",
  "entities": [
    {"type": "血压", "value": "155/95", "unit": "mmHg"},
    {"type": "症状", "value": "头晕"},
    {"type": "睡眠", "value": "差", "reason": "失眠"}
  ],
  "relations": [
    {"from": "患者", "to": "血压155/95", "type": "测量", "time": "T1"},
    {"from": "失眠", "to": "头晕", "type": "可能导致", "confidence": 0.8},
    {"from": "失眠", "to": "血压升高", "type": "可能导致", "confidence": 0.7}
  ]
}
```

### 4.4 Agent C：参谋监察（安全守门人）

**角色定义**：负责医疗合规性审查和上下文组装，是系统的"安全阀"和"智囊"。

**核心职责**：
- 在 Agent A 回复前，组装完整的上下文（当前输入 + 历史图谱 + 医疗指南）
- 对 Agent A 的输出进行医疗合规性审查
- 拦截任何违反医疗安全红线的回复
- 在紧急情况下触发 SOS 流程

**审查规则示例**：
```
规则 1：禁止建议调整药物剂量
  → 如果 Agent A 输出包含 "加一片"/"减半"/"停药" → 拦截

规则 2：禁止推荐食物-药物禁忌组合
  → 如果患者服用地平类药物 且 Agent A 提到 "西柚" → 拦截

规则 3：紧急情况识别
  → 如果血压 > 180/120 或出现 "胸痛"/"视力模糊" → 触发SOS

规则 4：心理危机干预
  → 如果检测到 "不想活"/"活着没意思" → 触发心理危机预案
```

### 4.5 实战场景：血压波动的多Agent协作

```
场景：张大爷（72岁）早上测量血压 160/100，高于其基线 135/85

Step 1: 数据输入
  → 蓝牙血压计自动上传数据
  → Agent B 将数据写入图谱，标记为 "异常升高"
  → Agent B 检索历史：发现张大爷连续3天血压偏高，
    且昨晚记录 "和儿子吵架，心情不好"

Step 2: 上下文组装 (Agent C)
  → Agent C 组装 Prompt：
    - 当前血压：160/100（高于基线）
    - 历史趋势：连续3天升高
    - 可能原因：情绪波动（与儿子吵架）
    - CDSMP策略：优先使用 "情绪管理" + "行动计划"

Step 3: 生成回复 (Agent A)
  → Agent A 生成共情回复：
    "张大爷，今天血压比平时高了一些，您别着急。
     我听说昨晚您和儿子有点不愉快？做父母的都不容易。
     咱们先做三个深呼吸，然后一起想想，
     今天做点什么让自己开心的事？"

Step 4: 合规审查 (Agent C)
  → Agent C 审查通过：无药物建议、无恐吓语言、符合CDSMP
  → 回复推送到智能终端

Step 5: 后续行动
  → Agent B 记录本次干预
  → 如果2小时后血压仍高 → Agent C 触发复测提醒
  → 如果持续3天异常 → 推送给社区医生
```

## 5. 动态时序知识图谱设计

### 5.1 为什么放弃传统 RAG？

| 对比维度 | 传统 RAG | 动态时序知识图谱 |
|----------|----------|------------------|
| 数据组织 | 文档分块 → 向量嵌入 | 实体-关系-时间三元组 |
| 时间维度 | ❌ 无法区分"昨天"和"去年" | ✅ 每个关系都有时间戳 |
| 因果推理 | ❌ 只能做相似度匹配 | ✅ 可以推理"A导致B" |
| 状态追踪 | ❌ 无法追踪趋势 | ✅ 可以识别"连续3天升高" |
| 可解释性 | ❌ 黑箱 | ✅ 图谱可视化，医生可审核 |

### 5.2 图谱本体设计

**核心实体类型**：
```
- Patient (患者)：基本信息、基线数据
- Medication (药物)：名称、剂量、频次、开始时间
- Symptom (症状)：头晕、头痛、心悸、失眠等
- VitalSign (生命体征)：血压、心率、体重
- LifeEvent (生活事件)：家庭变故、饮食变化、运动
- Emotion (情绪状态)：焦虑、抑郁、愉快、愤怒
- MedicalVisit (就诊记录)：医院、诊断、医嘱
- FamilyMember (家庭成员)：关系、联系方式、支持力度
```

**核心关系类型**：
```
- [:测量_AT {time}] → 生命体征
- [:服用_SINCE {start_time, end_time}] → 药物
- [:经历_AT {time, duration}] → 症状
- [:导致 {confidence}] → 因果推理
- [:缓解_BY {time}] → 干预效果
- [:关联 {type}] → 家庭成员
- [:就诊_AT {time}] → 就诊记录
```

### 5.3 图谱查询示例 (Cypher)

```cypher
// 查询：张大爷最近一周的血压趋势
MATCH (p:Patient {name: "张大爷"})-[:测量_AT]->(v:VitalSign)
WHERE v.type = "血压" AND v.time > datetime() - duration({days: 7})
RETURN v.time, v.value
ORDER BY v.time

// 查询：与"血压升高"相关的历史因素
MATCH (factor)-[:导致 {confidence: 0.7..}]->(s:Symptom {name: "血压升高"})
WHERE factor.time > datetime() - duration({months: 3})
RETURN factor.type, factor.value, count(*) as 频次
ORDER BY 频次 DESC

// 查询：当前用药方案
MATCH (p:Patient {name: "张大爷"})-[:服用_SINCE]->(m:Medication)
WHERE m.end_time IS NULL
RETURN m.name, m.dosage, m.frequency
```

## 6. 开源框架选型与二次开发方案

### 6.1 核心理念：不造轮子，搭积木

使用成熟的开源 Agent 框架进行二次开发，可降低 **70%** 的底层工程难度，将精力集中在**业务逻辑**和**Prompt 调优**上。

### 6.2 Agent ABC 开源基座选型

| Agent | 推荐开源基座 | GitHub Star | 核心优势 |
|-------|-------------|-------------|----------|
| **全局编排层** | **LangGraph** | 12万+ | 图状态机、状态持久化、Human-in-the-Loop 原生支持 |
| **Agent B (记忆)** | **Zep / Graphiti** | 2.8万+ | 时序知识图谱引擎，自带时间戳标注和实体抽取 |
| **Agent C (安全)** | **NVIDIA NeMo Guardrails** | 3万+ | 企业级AI安全护栏，支持 Colang DSL 定义规则 |
| **Agent A (交互)** | **Pipecat** | 1.5万+ | 开源语音AI框架，处理VAD/延迟/流式合成 |
| **快速验证** | **Dify / FastGPT** | 8万+ | 低代码平台，可视化Prompt编排，快速出MVP |

### 6.3 各模块二次开发要点

#### 6.3.1 编排层（LangGraph）

**你要做的**：
- 定义 A、B、C 的流转顺序（状态图）
- 配置 Redis 作为状态持久化存储
- 设置 Human-in-the-Loop 检查点

**Cursor 自动生成的**：
- LangGraph 的 `StateGraph` 定义代码
- 节点（Node）和边（Edge）的连接代码
- 状态持久化和断线重连逻辑

#### 6.3.2 记忆层（Zep/Graphiti）

**你要做的**：
- 定义医疗领域的"本体（Ontology）"
- 指定需要重点抽取的实体类型（血压、药物、症状）

**Cursor 自动生成的**：
- Zep Python SDK 的集成代码
- 实体抽取 → 图谱写入的流水线
- 适配器模式封装（方便日后更换框架）

#### 6.3.3 安全层（NeMo Guardrails）

**你要做的**：
- 整理医疗红线规则（禁忌症、药物交互）
- 用 Colang 语言定义拦截规则

**Cursor 自动生成的**：
- Guardrails 配置文件
- 拦截器函数的集成代码
- 与 LangGraph 状态机的对接

#### 6.3.4 交互层（Pipecat）

**你要做的**：
- 打磨基于 CDSMP 框架的 Prompt 模板
- 注入共情话术和 Few-shot 示例

**Cursor 自动生成的**：
- 语音交互管道（STT → LLM → TTS）
- WebSocket 长连接代码
- 音频流编解码和断线重连

### 6.4 二次开发避坑指南

## 8. AI辅助开发工作流 (Cursor)

### 8.1 为什么选择 Cursor？

Cursor 是 2026 年全球最领先的 AI 编程 IDE（已被 SpaceX 收购，整合 Grok 4.5 模型）。它不是传统代码编辑器，而是一个**多智能体编程协作平台**。

**核心优势**：
- **Multi-Agents 模式**：最多 8 个 AI 程序员同时工作
- **深度上下文理解**：能理解跨文件的复杂架构逻辑
- **Composer 编排**：一次性生成多文件项目骨架

### 8.2 项目配置文件 (.cursorrules)

在项目根目录创建 `.cursorrules` 文件：

```markdown
# 项目角色与背景
你是一个资深的医疗AI架构师和全栈工程师。我们正在开发一款
"基于CDSMP框架的高血压老年人自我管理支持系统"。
核心载体是适老化智能终端，后端采用多Agent协同与动态时序知识图谱。

# 核心架构约束 (必须严格遵守)
1. 多Agent分工：
   - Agent A (健康教练)：负责前端语音交互，必须遵循斯坦福CDSMP框架
   - Agent B (记忆局长)：负责维护Neo4j时序知识图谱
   - Agent C (参谋监察)：负责图谱检索和医疗合规性拦截
2. 数据层：使用 Neo4j 存储带时间戳的实体与关系
3. 通信协议：终端与后端通过 MCP 或 WebSocket 进行流式交互

# 技术栈要求
- 后端：Python (FastAPI) + LangGraph
- 数据库：Neo4j (图谱) + Redis (会话状态)
- 开源基座：Zep(Graphiti) + NeMo Guardrails + Pipecat

# 编码规范
- 使用适配器模式隔离业务逻辑与框架代码
- Agent A 的 Prompt 模板必须包含 CDSMP 策略的 few-shot 示例
- 涉及医疗建议的代码，必须加入 Human-in-the-loop 拦截器
- Agent B 写入图谱前必须做确定性校验
```

## 9. 安全合规与适老化设计

### 9.1 安全设计

#### 9.1.1 三层安全架构

```
第一层：Agent C 实时拦截
  → 对每条 Agent A 的输出进行合规性审查
  → 拦截药物建议、食物禁忌、恐吓性语言

第二层：Human-in-the-Loop
  → 高风险操作（如调整用药）推送给社区医生审核
  → 医生确认后才执行

第三层：本地数据沙箱
  → 敏感健康数据本地存储，不上传云端
  → 云端仅传输脱敏后的特征向量
```

#### 9.1.2 紧急预案

| 紧急情况 | 触发条件 | 系统响应 |
|----------|----------|----------|
| 高血压危象 | 血压 > 180/120 | 语音安抚 + 自动拨打120 + 通知家属 |
| 心理危机 | 检测到轻生言论 | 心理危机话术 + 通知家属 + 推送心理热线 |
| 跌倒检测 | 手环加速度异常 | 语音确认 + 无应答自动报警 |
| 设备离线 | 超过12小时无数据 | 通知家属 + 社区医生上门 |

### 9.2 适老化交互设计

#### 9.2.1 设计原则

| 原则 | 具体实现 |
|------|----------|
| **零学习成本** | 语音为主交互，无需触屏操作 |
| **容错保护** | 任何误操作都可撤销，无破坏性操作 |
| **大字体高对比** | 最小字号 24pt，黄黑高对比配色 |
| **方言支持** | 支持普通话 + 主要方言识别 |
| **情感语音** | TTS 使用温暖、缓慢、有节奏的语音 |
| **主动关怀** | AI 主动发起对话，不依赖老人操作 |

#### 9.2.2 交互场景示例

```
场景 1：早晨问候
  AI（主动）："王大爷，早上好！今天天气不错，
              您昨晚睡得怎么样？"
  用户："还行，就是起夜了两次"
  AI："起夜两次还好，不算多。咱们先把今天的血压量一下，
      量完了我帮您记上，好不好？"

场景 2：用药提醒
  AI（药盒亮灯）："王大爷，到吃降压药的时间了。
                  白色小圆片，饭后一片，我帮您倒好温水了。"
  用户："今天不想吃"
  AI："理解您，天天吃药确实烦。不过您想想，
      上次您坚持吃药那段时间，血压多稳当，
      还能带孙子去公园呢。咱们今天也坚持一下？"

场景 3：紧急求助
  用户："我头好晕"
  AI："王大爷，您先坐下来，别着急。
      我帮您量一下血压……165/100，比平时高一些。
      您先深呼吸三次，我陪着您。
      我已经通知了您女儿和社区李医生，
      他们很快就会联系您。"
```

## 10. 商业落地路径

### 10.1 三阶段规划

#### 第一阶段：MVP 验证（0-3个月）

**目标**：验证 CDSMP 框架 + 多Agent 的业务可行性

- 使用 Dify/FastGPT 快速搭建 Agent A 原型
- 对接单一 LLM（如 Qwen），实现基础对话
- 招募 30 名高血压老人进行封闭测试
- 核心指标：用药依从性提升率、用户满意度

#### 第二阶段：软硬一体化（3-9个月）

**目标**：完成智能终端量产准备

- 集成 LangGraph + Zep + NeMo Guardrails 完整后端
- 完成"健康守护相框"硬件设计与小批量试产
- 对接蓝牙血压计、智能手环
- 扩展测试至 200 名用户，覆盖 3 个社区

#### 第三阶段：服务模式（9-18个月）

**目标**：建立可持续商业模式

- **B2G 模式**：与社区卫生服务中心合作，纳入慢病管理体系
- **B2C 模式**：子女购买终端 + 月度服务费（99元/月）
- **B2B 模式**：与药企合作，提供用药依从性数据服务
- **数据服务**：匿名化健康数据为药企研发提供洞察

### 10.2 核心竞争壁垒

```
1. 理论壁垒
   → 斯坦福CDSMP框架的系统性AI化，国内首创

2. 数据壁垒
   → 动态时序知识图谱积累的个人健康画像，越用越准

3. 体验壁垒
   → 适老化设计 + 情感陪伴，不是冰冷的医疗设备

4. 生态壁垒
   → 智能终端 + 外设生态 + 社区医生网络
```

### 10.3 风险与应对

| 风险 | 应对策略 |
|------|----------|
| 医疗事故责任 | 严格遵守"不建议用药调整"红线 + 购买产品责任险 |
| 老年人接受度低 | 子女购买决策 + 社区医生推荐 + 免费试用 |
| 数据隐私合规 | 本地数据沙箱 + 脱敏上传 + 符合《个人信息保护法》 |
| 技术迭代风险 | 适配器模式架构 + 持续关注开源生态 |
